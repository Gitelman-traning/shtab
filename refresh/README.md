# Утреннее обновление Штаба

Worker `shtab-collect-scheduler` проверяет витрину каждые 15 минут с 05:07 до 11:52 МСК. Если вчерашние показатели не подтверждены, запускает `shtab-collect.yml` через GitHub `repository_dispatch` (`shtab_collect`). Штатное расписание GitHub в 05:17 МСК остаётся запасным.

Проверяются состояния всех источников и наличие 41 дневной точки: общие показатели и семь маркетинговых источников. Подтверждённый ноль считается данными. Сборщик после записи сделок читает цифры обратно через `/api/points`; неполная запись отмечается как `partial`, а не `success`.

Блокировка в `collector_refresh` (schema46.sql) разрешает повтор через 40 минут — после 30-минутного таймаута задания. Неудавшийся вызов GitHub снимает блокировку. Параллельные задания сериализуются `concurrency` в GitHub. Если исходная выгрузка ещё не готова, проверка `export_date` блокирует публикацию; следующий утренний запуск повторит попытку. После 11:52 МСК попытки продолжатся следующим утром; состояние и дата последнего успеха видны в разделе статуса Штаба.

Секреты `GH_DISPATCH_TOKEN` и `INGEST_TOKEN` берутся из Doppler `gitelman/prd_cf_shtab`, передаются Worker через `wrangler secret bulk`. Первый разрешает запуск workflow, второй защищает служебный `POST /run`; `POST /run?dry=1` только проверяет свежесть. `GET /health` не раскрывает данные.

Выпуск: применить schema46.sql к D1 `shtab`, затем из `refresh/` выполнить `wrangler deploy` и установить секреты. Основные настройки — в wrangler.toml, данные проверок — в D1. CRM и исходная таблица этим Worker не меняются.

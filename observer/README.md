# Наблюдение за триггерами amoCRM

Worker `shtab-amo-observer` получает независимый `add_message` webhook. В той же
D1 `shtab` хранятся сообщения, копии правил и три чтения сделки: сразу после
доставки, через 1 и 5 минут. Страница `/settings/amo-watch/` и API
`/api/amo-watch` доступны только администраторам Штаба. Срок хранения 30 дней.

В CRM выполняются **только GET**. Автоматических исправлений, отправок клиентам,
примечаний и тегов в этом сервисе нет. Настройка подписки — отдельный шаг выпуска.
Правила наблюдения — независимые копии условий F5, изменения применяются только
к новым сообщениям. Не выводить текст сообщений, контакты и секретный URL в логи.

Первое правило — копия известного блока F5 №131 (Ильнара). ID воронки приведён к
числовому ID amo 8733326. Это не утверждение о том, как F5 сравнивает ведущий ноль
в исходном условии. Источник — поле 1439087, значение «Интеграции» 1223105.

Для связи со сделкой используются ссылка на сделку из webhook либо беседа
`GET /api/v4/talks/{id}`. Выбор «последней сделки контакта» запрещён. Перед чтением
проверяется связь контакта и сделки. При задержке привязки/ошибке API — до двух
дополнительных попыток на фазу. Результаты чтений сохраняются идемпотентно по фазе.
Первая успешная привязка фиксируется для следующих чтений. Она может возникнуть
позже самого входящего сообщения. Это **не** исторический снимок этапа F5.
Присутствие тега/источника не доказывает, кто их установил. Причины внутренних
отказов F5 доступны только в его собственном отладчике.

Выпуск:

1. Сохранить D1 Time Travel bookmark; применить `schema45.sql`.
2. Задать секреты Worker `AMO_TOKEN`, `HOOK_KEY` через Doppler / Wrangler stdin.
3. Выпустить Worker с `observer/wrangler.toml` (cron раз в минуту).
4. Создать **отдельную** подписку amo `/api/v4/webhooks`, `settings: ["add_message"]`,
   адрес Worker `/hook/<HOOK_KEY>`. Другие подписки не изменять. Проверить GET
   подписок: адрес, событие и `disabled: false`; записать в `amo_watch_health`
   строку `subscription=active`. Секретный адрес не печатать.
5. Выпустить сайт Штаба штатным push в master; проверить страницу, API и соседние разделы.

При доставке события запись в D1 завершается до ответа 200. Ошибка хранения
возвращает 503, чтобы amo могла повторить доставку. Повторы дедуплицируются по
аккаунту и ID сообщения. Очередь использует аренду записи на 4 минуты. Cron
обрабатывает до 15 событий за запуск; задержка видна по фактическим временам.
Прошлые сообщения не импортируются. Для проверки канала не отправлять клиентам
сообщения: дождаться обычного входящего.

Проверки: `node --experimental-sqlite --test tests/amo-watch.test.mjs` из корня
Штаба и полный `tools/predeploy.sh` перед push.

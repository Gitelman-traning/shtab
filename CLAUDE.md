# Штаб — правила для работы через Claude Code

Читай этот файл перед любой задачей. Он общий для всех, кто работает над проектом.

## Что это
Штаб — центр компании: витрина показателей (Cloudflare D1) + API + сайт с разделами подразделений (Cloudflare Pages, проект `okk-dashboard`).
Боевой адрес: https://shtab-20v.pages.dev. Вход по личному логину; права по разделам выдаёт админ на странице «Пользователи».
Документы, раскладки источников, планы и разборы — в приватном репозитории `shtab-docs` (спрашивай доступ у Никиты).

## Где что лежит
- `site/public/` — страницы. Каждая страница — отдельный html с `/ui.css`, `/ui.js`, `/nav.js`; данные берутся из `/api/points` и других API.
  - `sales/l1/` — Первая линия (менеджеры, окна на день), `sales/l2/` — Вторая линия и ОКК (страницы ОКК собираются из репозитория `okk`, в git не попадают),
  - `marketing/` — источники (страницы генерируются из `site/src/source.tpl.html` и `web.tpl.html` скриптом `build.py`),
  - `index.html` — общий экран, `tags.html`, `users.html`, `budget.html` — настройки (только админ),
    `settings/dashboard/` — личный дашборд проектов Никиты: три вкладки показывают страницы из KV (`/api/dashboard`), которые присылает его локальная сборка (`Local/dashboard/publish.mjs`); в git их нет.
    `api/tgtask.js` — вебхук бота Штаба: Никита пересылает сообщение коллеги или пишет задачу → очередь в KV, её забирает `Local/dashboard/sync.mjs`.
  - `hr/` — HR: структура компании, праздники, отпуска (открыто всем) и «Для HR» (закрыто по умолчанию, открывается «правкой» на разделе HR);
    API в `functions/api/hr/` (`_hr.js` — даты, праздники, остаток отпуска), напоминания HR в Telegram — `hr-remind.yml` → `/api/hr/remind`.
- `site/functions/api/` — API (Cloudflare Functions). `_lib.js` — права, сессии, `sectionOf()` (какой раздел отвечает за адрес).
- `site/public/nav.js` — единое меню: новый раздел добавляется в дерево `TREE` здесь и в `SECTIONS`/`sectionOf` в `_lib.js`.
- `collector/` — ночные сборщики (GitHub Actions `shtab-collect.yml`): `collect.py` — из выгрузки amo в Google Sheets, `okna.py` — окна Первой линии прямо из amo, `metrika.py` — Яндекс Метрика.
  `prep.py` + `prep_prompt.md` — подготовка диагноста к встрече (`prep.yml`, каждые 30 минут днём + вебхук amo): сделки на этапе «Встреча подтверждена» → досье с веб-поиском, похожие участники, подготовка → `/sales/l2/prep/`.
- `schema*.sql` — миграции D1, по порядку номеров; новая миграция = новый файл `schemaN.sql`, старые не править.
- `metrics.json` — реестр показателей (id, название, раздел, единица, определение).
- `build.py` — сборка сайта: страницы источников из шаблонов + страницы ОКК из соседнего `../okk`.

## Как проверять
- Страницу — локально: `python tools/local.py 8766` отдаёт `site/public` и проксирует `/api/*` на боевой с твоей сессией
  (токен сессии в файле `site/.session.local`, см. `tools/local.py`). Чистые адреса: `/tags` → `tags.html`, `/x/` → `x/index.html`.
- Выкладка: проект Cloudflare Pages привязан к репозиторию — слияние в `master` собирает сайт (`cf-build.sh`) и выкладывает его само.
  Локальный `wrangler pages deploy` не нужен (остаётся у Никиты на крайний случай).
- Миграцию к боевой базе применяет Никита: `cd site && npx wrangler d1 execute shtab --remote --yes --file ../schemaN.sql`.
- Сборщик локально: переменные окружения как в `shtab-collect.yml`; ключи не коммитить.

## Правила
1. Секреты (токены amo, ключи сервис-аккаунта, токен сборщика, сессии) — только в переменных окружения и GitHub Secrets. В код и в git — никогда.
   Файлы `*.local.*`, `.env`, `site/public/sales/l2/`, `guide.html` уже в `.gitignore`.
2. Работай в своей зоне (см. `.github/CODEOWNERS`): маркетинг — `site/public/marketing/` и шаблоны источников, продажи — `site/public/sales/`,
   витрина и сборщики — координатор. Чужую зону не правь без владельца.
3. Без pull request (решение Никиты 05.10.2026): изменения сохраняются прямо в `master` коммитом с понятным описанием на русском,
   Cloudflare выкладывает сам. Перед push — `git pull --rebase origin master` (параллельно работают другие сессии).
   После выкладки — проверка прода: изменённая страница и соседние разделы (общий экран, Первая и Вторая линия, маркетинг),
   Никите одна строка «выложено», без скриншотов и отчёта о проверках. Сломалось — `git revert` этого коммита и push. Долгую работу можно вести в ветке, но в `master`
   её вливаем сами, без PR. Если к Штабу подключатся коллеги со своими правками — PR возвращаем.
4. Стиль: русский язык интерфейса, стиль Штаба (`ui.css`, тёмная и светлая темы, мобильная ширина от 360 px).
   Воронки — по мягкому правилу «лестница» (STYLE.md в `shtab-docs`). Слово «когорта» в интерфейсе не используем.
5. Запросы к D1 без коррелированных подзапросов (они сожгли лимит чтений): «последний снимок» — одним `GROUP BY`.
6. Данные клиентов (имена, телефоны, содержание встреч) не выводить в логи и не коммитить в публичные репозитории.
7. Не ломать чужие страницы: `nav.js` и `ui.css` общие, правки в них проверяй на 3–4 страницах разных разделов.

## Кто за что отвечает
Координатор проекта — Никита (админ Штаба, витрина, сборщики, деплой, права). Владельцы разделов — в `.github/CODEOWNERS`.
Вопросы по данным amo и таблицам — к Никите; по методике ОКК — к руководителю Второй линии; по окнам Первой линии — к Людмиле.
